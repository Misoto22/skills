# Changelog

All notable changes to this repository are documented here.

## 0.16.1 — 2026-09-05

- `bump-version.py` reports a declared file that stopped carrying the current version, instead of walking past it. The bumper moves a version by replacing the string it finds, so a file holding a different one is skipped and says nothing — which is what a merge does when it resolves one manifest to the older side. `resolve_current` compared the JSON manifests to each other and nothing compared the text entries, where every `SKILL.md` version lives, so the drift surfaced only when `validate-repository.py` ran, by which point it was committed. `--check` and a bump both name the stranded file now, and the bump refuses **before** writing anything: a half-applied bump leaves the repository in the state the check exists to catch, one commit closer to a tag describing artefacts that disagree with it.
- Twice in one afternoon, which is why it is worth a guard rather than a habit. A rebase resolution left `reunite`'s `SKILL.md` at `0.15.0` while everything around it moved, and two consecutive bumps walked past it in silence. Independently, `handoff`'s `SKILL.md` was declaring `0.15.0` on `main` at `22e526d` and turned `main`'s CI red — `validate-repository.py` said `metadata.version must be 0.15.2` while `bump-version.py --check` reported no drift at all. The `0.16.0` release repaired that one; this is the check that would have caught both a step earlier, where the preflight is cheap.

## 0.16.0 — 2026-09-05

- Added `reunite` to `dev`. Claude's desktop app keeps one sidebar index per signed-in account under `claude-code-sessions/<account>/<org>/`, so signing in as a second account empties the sidebar. Nothing was ever deleted: the transcripts under `~/.claude/projects/` carry no account field at all, which is why `claude --resume` had been listing every one of them the whole time. Only the index is partitioned. `reunite` unions those indexes so whichever account is signed in sees the whole history — reporting the plan, the accounts and the bytes before writing, only ever adding files, and recording each one so `--undo` takes back exactly those. On the machine it was built on that was 720 entries and 114MB across three accounts.
- It also reconciles titles, because a rename writes one index file. Once a conversation lives in three indexes, renaming it under one account leaves the other two holding the old name, and a union cannot fix that: the entry is already there, so the copy pass skips it. The naming sweep and the union were undoing each other, and every account switch showed stale names again. Where copies of one conversation disagree, the most recently written file wins and its `title`, `titleSource` and `previousTitles` are written into the others; nothing else in those files moves. File mtime is the signal because it is the only timestamp a rename actually moves — `lastActivityAt` records the conversation, not the record of it. It is not infallible, so every reconciliation is listed by name and `--no-titles` turns the pass off.
- "Signed in" means the desktop app, not the CLI. They hold separate logins and are routinely on different accounts, so `~/.claude.json` answers a different question — it names the account `claude` authenticates as, not the one whose sidebar is on screen. Measured here, the two disagreed: `~/.claude.json` reported one account while a rename landed in another, the one the app records as `lastKnownAccountUuid` in its own `config.json`. `--into=current` had been targeting an index nobody was looking at.
- Added `handoff` to `dev` — a live mirror between Claude Code and Codex. The two tools converged on exactly the two mechanisms a bridge needs: they fire hooks on the same events under the same configuration shape, down to `~/.codex/hooks.json` using Claude Code's schema and its environment variable names, and both append their history as one JSON object per line while the conversation runs. So a hook on either side can read what accumulated since it last looked and write it into the other side's format. The rest is a field-name table.
- Two things the existing converters get wrong, both of which look like success. Writing the Claude transcript alone produces a file nothing displays: the desktop app lists conversations from its own index, in the account it is actually signed in as. And registering in Codex's SQLite writes a row its scanner regenerates — `local_thread_catalog` is a projection derived from the rollout files, which are the only source that matters there.
- A mirror is always a new conversation on the receiving side; appending into a history the other tool has open races its own writer. Each side keeps a byte watermark so a `PostToolUse` hook firing two hundred times translates each exchange once, and reads stop at the last newline because the hook fires mid-write. The hook writes nothing to stdout and always exits 0 — its output is read as feedback by the agent that ran it, and a non-zero exit can stop a turn — so failures are recorded in the state file and surface through `status`.
- What a mirror is not: a resumable replay. Codex encrypts its reasoning under its own key and Claude signs its thinking blocks, and neither signature is reconstructible from the other side's text, so reasoning arrives as plain text where it survives and is dropped rather than forged where it does not.
- `handoff`'s own manifest needed a hand edit this release, which is the bug worth naming. `bump-version.py` rewrites occurrences of the *current* version string, and a skill scaffolded between releases carries whatever version the scaffolder wrote — 0.15.0 here, against a repository at 0.15.2. The bumper could not see it and `--audit`, which greps for the new version, could not either. A skill can therefore land on `main`, be published in the marketplace, and ship a manifest a release never touched.

## 0.15.0 — 2026-09-05

- Added `steward` to `dev` — the 大内总管. `sync`, `ship` and `cleanup` each work in the repository they are run in, and nothing ran them across the dozen a person actually has open; which branches were waiting to be merged was whichever ones someone remembered. The steward finds every active repository from where sessions leave traces — Claude Code's transcripts and running sessions, Codex's thread catalogue, and any roots named — resolves each worktree to its primary checkout, runs sync, cleanup and retitle in each, and returns one ledger: ready to merge, blocked and why, unshipped, stale, kept.
- Two things it owns that the delegated skills cannot see. **Occupancy**: a worktree with a live process, or with session activity inside a window, is never removed and its branch never deleted, whatever git and the forge say about the branch — a session resumed into a deleted directory breaks every command after it, and git cannot see the session. **Unattended mode**: every question a pass would have stopped to ask lands in the report instead of blocking a run nobody is watching, and `retitle` proposes without writing, for the reason its own confirmation table exists.
- It is the first skill to declare `context: fork`. A sweep is the case CONTRIBUTING describes for it — a long private session whose transcript the caller never needs. Measured on one machine, one run covered 15 repositories, 121 worktrees and 44 open pull requests, and none of that intermediate traffic is what was asked for. Forked, the report is the whole delivery rather than a summary sitting on evidence the caller can scroll to, which is why it is written to `~/.local/state/steward/last-sweep.md` before it is returned and why the report names that path.
- It never merges. A green pull request is reported with the command that would land it, because whether it should land today — a review still expected, a deploy window, a change meant to go in first — is not visible from a sweep. `scripts/inventory.py` is the discovery half: standard library only, opening the Codex catalogue read-only, and tested against real repositories and forged session stores.
- `ci-pins.py`'s usage example moved off `ruff 0.15.0`. The version in it is arbitrary — it demonstrates `bump`, and ruff is pinned at 0.14.6 — but `bump-version.py --audit` greps for the repository's own version string, so the example collided with this release and failed the audit CI runs. It now shows the pin's next patch, which is both what a reader would actually type and a number this repository does not use.

## 0.14.0 — 2026-09-05

- Every `chinese-metaphysics` skill validates its artifact with a script instead of asking the model to do it by reading JSON. The four reading skills each told the model to "use the vendored `shared/bazi/artifacts.py` validator" and to stop on a missing hour pillar, wrong weights, or an arithmetic mismatch; `validate_envelope` checks schema, version and checksum, has no CLI, and detects none of those things. The two chart skills and the compatibility calculator asked for the same list as a bullet list to eyeball. So six of the seven named a completion criterion nothing could meet, and the seventh named it twice. `scripts/validate_artifact.py` now ships in all seven, exits 2 with every defect named, and the prose says run it and stop on 2.
- What the new `shared/bazi/validation.py` catches is the class of defect a checksum cannot: an artifact assembled or edited by hand hashes exactly as cleanly as a computed one, because whatever produced it hashed it too. A chart short its hour pillar, five element percentages that no longer sum to a hundred, a comparison whose weights disagree with the model it declares or whose general score its own five dimensions do not produce, a contextual score with no profile to audit it against, a 命盘 with eleven palaces or two life palaces, a 化忌 landing on a star that sits in no palace, decade ranges that reverse halfway. Each was named in prose and each reached a report as a confident paragraph about evidence that was never there.
- One rule is checked in the cross-reading and nowhere else, because no single artifact can hold it: that both charts are one person at one moment. Each file is impeccable alone, and a BaZi chart cast for one moment against a 紫微 chart placed for another produces a comparison that reads as authoritative and means nothing. The gate compares the resolved Gregorian date rather than the entered one — a lunar-entered chart and a gregorian-entered one for the same birth are the same moment, and refusing that pair would be the check inventing a defect of its own — and it refuses a pair where only one side carries a day-boundary alternate, which both systems emit on exactly a 23:00-23:59 true solar hour.
- Defects are collected rather than raised on the first one, and structure is reported before the hash. "the hour pillar is missing" tells someone what to fix; "the checksum no longer matches" tells them only that something is wrong, and an edited artifact produces both. A wrong schema stops the run instead of joining the list, so handing a chart to the 紫微 gate reports one defect rather than twelve about an artifact nobody supplied.
- `compatibility.py` asks the same module rather than keeping its own `_validate_chart_shape`. Two copies of "what a complete chart is" is how a comparison comes to accept a source its own reading skill then refuses, and the copies had already drifted: the comparison checked four pillars and a distribution, the reading skill's prose promised nine things.
- An artifact that omits `sensitivity.alternate_day_boundary` entirely is refused rather than read as "no alternate". That is the one wrong answer available: every reading skill has to tell a person whether the 23:00 boundary choice moved their chart, and an absent flag is indistinguishable from a confident no.
- Counting the elements, not only summing them. A distribution that dropped the one element a chart has none of still sums to 100, because that element's share rounds to zero — and the element a chart is short of is most of what a reader came to hear. A test asserts that case specifically, on a chart whose 水 is genuinely 0.00.
- The mean-solar ephemeris double moves to `tests/bazi_skill/ephemeris_double.py`, where two test modules had a copy each and a third was about to add one. It also lets the Zi Wei and cross gates be tested without `pyswisseph`: a suite that skips itself when the AGPL C extension is missing tests nothing on the machine most likely to be missing it.

- `photo-abstract-editorial-native` composes by running `scripts/compose_board.py` instead of asking the model to re-derive the geometry. The ratio table, the shrink-only fit, the 0.1% aspect tolerance and the three manifest booleans were arithmetic written as prose, and the two failures the skill exists to prevent — a soft upper photo and a squashed lower panel — are exactly what a re-derivation gets wrong. The booleans are now measured rather than asserted: an upscale or a ratio drift ends the run naming the measurement, before a board reaches disk, where the old wording could only ask for `aspect_ratio_preserved: true` and be told it. `references/composition-contract.md` stays as written, because the evaluation runner scores a skill from its text and cannot execute a script — the contract is the explanation and the script is the implementation. Pillow is declared in the skill's own `requirements.txt` and imported lazily, so `--help` still answers on a machine that has not installed it, which is the environment the runner renders it in.
- Writing the geometry down found something the prose could not say: **every portrait source takes the side-by-side exception.** The tall row of the ratio table reserves enough lower canvas that no ratio at or below `0.85` yields a standard board inside the `1.8 ×` trigger, so that row sizes the board the trigger measures rather than one that is ever delivered. The contract says so now, and a test holds it — a change making a stacked portrait board reachable is a change to the contract, not a refactor.
- The three example boards were 2.2, 3.0 and 3.3 MB of JPEG embedded directly in `SKILL.md`, and nothing rendered them: the evaluation runner drops binaries from a prompt, so the agent carried the links and never saw a pixel. They are re-encoded to under 300 KB each — they carry proportion, not detail, and the aspect drift is a fortieth of the tolerance the contract sets for the boards themselves — and the gallery moves to the reader documents, which is where a person deciding whether to install something actually looks. `SKILL.md` keeps one pointer line. A test holds the budget, since a replacement asset is how it silently returns.
- `tests/photo_abstract_editorial_native/` had no `__init__.py`, so `unittest discover` skipped it and the skill's contract test had never run. It runs now, alongside nineteen new cases that drive the composer through its CLI.
- The `SKILL.md` change was gated against the tree it replaced, by scoring both splits twice — once on `HEAD`'s body and once on this one. Routing passes 5 of 5 tuning and 2 of 2 holdout, which the unchanged description already predicted, since `--run` judges from descriptions alone. The behavior cases are the half that reads the body, and they score identically either side of the edit: `portrait-lower-space` fails two expectations and `derivative-fallback` fails one, before and after. So the gate is a non-regression rather than a rise, which is what a change of shape — prose replaced by a command, a gallery pruned — can honestly claim; nothing here was aimed at a behavior case.
- **Both behavior cases were already failing, and this release does not fix them.** Both want a derived value the skill does not produce: the lower-canvas height read off the portrait rule, and a sidecar marking the top source `derivative-fallback`. The runner has no filesystem, so a skill whose step 2 is now a command has one more reason to answer with the command instead of the derivation — a risk the measurement says has not landed yet, and the thing the next iteration on this skill should take as its tuning target.

## 0.12.0 — 2026-09-04

- `retitle` names in English by default, and `--lang=zh` keeps the Chinese vocabulary it started as. The scheme is unchanged — same fullwidth separator, same creation-date rule, same closed set of nine, same preview table — and only the words move: `MMDD｜TYPE｜subject` against `MMDD｜类型｜主题`. For new sessions the same choice is one environment variable on the hook's own command, `SESSION_TITLE_LANG=zh`, set in the `settings.json` entry rather than a shell profile so the next reader of that file can see it; a locale tag such as `zh-CN` resolves, and anything unrecognised falls back to English rather than failing, because a rule in the wrong language still names the session and a hook that refuses to emit one does not.
- The English types are five uppercase letters — BUILD, SHAPE, PATCH, TWEAK, SHIP, PROBE, WRITE, AUDIT, STUDY — and that is the whole design, not a stylistic choice. The type field's second job is to hold a column so the subject starts at the same x on every row, and Chinese did it for free: every han glyph is one em, so 优化 and 研究 are the same width by construction and nobody had to decide anything. English in a proportional UI font has no such property, and the natural words are its worst case — `FIX` beside `DESIGN` is a factor of two, and at that spread there is no column left to read. Fixing the letter count brings the nine to about 3px of spread across roughly 38px, under a tenth of a glyph, and uppercase takes the rest: capitals have neither ascenders nor descenders, and the field reads as a tag rather than as a word competing with the subject beside it. `SHIP` is the single four-letter member and is chosen rather than settled for — no honest five-letter verb covers commit, PR, merge, tag, deploy and publish at once, and `MERGE` would hold the column by describing one member of that set as though it were all of them. One ragged character on one of nine types costs less than a type that lies.
- The language reaches the whole run, not only the titles. The preview table's header is `| OLD | NEW |` in English and `| 原名称 | 新名称 |` in Chinese, and the summary beneath it and the closing report follow the same choice — a skill whose entire premise is that a sidebar should not be half one language and half another cannot hand back a report that is exactly that. The header had been Chinese in every run since the skill shipped, which nobody noticed while the titles were Chinese too.
- The subject is capped rather than counted. Chinese asked for four to twelve characters; English asks for two to four lowercase words and at most 24, because English runs about two and a half times wider for the same meaning — `批次文字显示` is six glyphs where `batch text rendering` is twenty. Swapping the vocabulary without moving that limit would have relocated the truncation from the end of the title to the middle of it, which is the failure the column exists to prevent.
- **A title already conforming in either language is kept.** Without that rule, changing the default would have made the first English run rewrite every Chinese title in the store — several hundred renames nobody asked for, on a sidebar someone had spent months naming. Moving a store from one language to the other stays a deliberate request, and when it is asked for every conforming title becomes a row in the preview table like any other.

## 0.11.0 — 2026-09-04

- Added `retitle` to `dev` (`/dev:retitle`): one naming scheme, `MMDD｜类型｜主题`, applied to both halves of a conversation list that sorts by nothing. The batch half renames what already exists, proposing every rename as a two-column table before writing one, keeping the original name where the subject cannot be recovered rather than inventing one, and excluding rows under a `chatgpt:` host because the cloud is their source and a local write is reverted at the next sync. The live half is a `UserPromptSubmit` hook shipped in the skill's `assets/` and installed as part of applying it — without that, a client re-generates its own titles faster than anyone renames them and the scheme decays from the front. The hook fires the full rule on a session's first prompt and a short re-check every fifth prompt after, because a session's direction drifts while the full rule is too long to inject every turn; the re-check retitles only on a real change of subject, since a title that moves every few messages is worse than one slightly stale. It is dependency-free Python rather than the obvious shell, which needs `jq` to read the hook event and would be one more thing to be missing on whichever machine the skill was installed on, and every failure path exits 0 with no output — a hook that throws blocks the user's prompt, and no titling scheme is worth that.
- The Codex half writes through the app server's `thread/name/set`, not the catalogue. `local_thread_catalog.display_title` looks like the name store and is a derived read-model: Codex regenerates it from the conversation's first user message, so a direct write is undone the next time the scanner reconciles that thread. The authoritative name is `~/.codex/session_index.jsonl`, and the RPC is the same call the client's own rename command makes, which is why the catalogue is then rebuilt *from* the name rather than over it. Finding this retired a "30-day window" the skill had briefly documented as a rule — it was only the scanner's reconcile scope, and of 156 direct writes the ones it happened never to revisit looked permanent. A large batch is refused at the tail with `-32001 Server overloaded`, cleanly, so the skill sends about twenty at a time and decides what to resend by comparing the store against its plan rather than replaying the error list; driven from the store, the retry converges whether the attempt was rejected, dropped a reply, or died halfway.
- `类型` is nine, not eight. `研究` was defined as "read sources and reported findings; nothing built", which is literally true of an audit and swallowed every one of them — across 181 renamed conversations it held 90, half a sidebar reading the same word, which is a field carrying no information. `审计` separates them on the object rather than the outcome, because the outcome is identical: `审计` inspects something the user already owns against a standard, `研究` reads the outside world to answer a question. Drawing the line there is also what makes the split checkable rather than a matter of taste, and it is the distinction a keyword match cannot make — matching `审查`/`评估`/`检查` over the same set claimed twenty-five, and five of those were wrong in both directions a regex fails.
