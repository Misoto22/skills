# Synastry v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the astrology plugin's TXT contract with a strict, privacy-aware JSON v2 calculation artifact and an evidence-validated adaptive reading workflow.

**Architecture:** The calculator is split into request validation, uncertainty arithmetic, ephemeris access, and artifact writing. A single schema and integrity implementation lives in `plugins/astrology/shared/` and is vendored into both skills, so the calculator and reader enforce the same contract without crossing plugin-cache boundaries. The reading skill validates JSON into deterministic evidence IDs before prose generation and validates the resulting Markdown before accepting it.

**Tech Stack:** Python 3.11-3.13 standard library, `pyswisseph==2.10.3.2`, `tzdata==2026.3`, Agent Skills Markdown/YAML, JSON fixtures, `unittest`, GitHub Actions.

## Global Constraints

- Accept and emit `kind: "synastry-chart"` with `schema_version: "2.0"`; do not parse, emit, or migrate TXT.
- Support `exact`, `window`, and `date-only` time modes; only `exact` may emit houses, angles, sect, lots, or overlays.
- Use `swiss-only` by default and fail when return flags show another backend; allow Moshier only through explicit `allow-moshier` policy.
- Never switch house systems silently; polar Placidus/Koch failure must recommend `whole-sign` or `equal`.
- Keep identity ownership on distinct stable subject IDs; never infer names, locations, pronouns, salutations, genders, or relationship types.
- Use `minimal` privacy by default, omit `residence`, write atomically with user-only permissions where supported, and refuse overwrite unless `--overwrite` is explicit.
- Treat dignity, sect, lots, sign-boundary labels, aspect profiles, and evidence weighting as named conventions rather than raw measurements.
- Keep all code identifiers, comments, documentation, and commit messages in English.
- Change only the astrology plugin to `AGPL-3.0-or-later`; leave every other plugin and the repository-level license unchanged.
- Do not change the marketplace release version during implementation; a later release must use `scripts/bump-version.py`.

Implement deterministic JSON and a fail-closed validator:

```python
KIND = "synastry-chart"
SCHEMA_VERSION = "2.0"


def canonical_json(value: object) -> bytes:
    return json.dumps(
        value,
        ensure_ascii=False,
        allow_nan=False,
        sort_keys=True,
        separators=(",", ":"),
    ).encode("utf-8")


def payload_digest(document: Mapping[str, object]) -> str:
    unsigned = {key: value for key, value in document.items() if key != "integrity"}
    return hashlib.sha256(canonical_json(unsigned)).hexdigest()


def attach_integrity(document: Mapping[str, object]) -> dict[str, object]:
    result = copy.deepcopy(dict(document))
    result["integrity"] = {"algorithm": "sha256", "digest": payload_digest(result)}
    return result
```

- [ ] **Step 4: Implement DST ambiguity and nonexistence detection**

For a local wall time, construct fold 0 and fold 1 candidates, round-trip each candidate through UTC, and compare the returned local wall time. Reject nonexistent times; when both folds round-trip with different offsets, require `timezone_fold` or a reasoned `utc_offset_hours` override.

```python
def _valid_candidates(local_naive: datetime, zone: ZoneInfo) -> dict[int, datetime]:
    candidates = {}
    for fold in (0, 1):
        aware = local_naive.replace(tzinfo=zone, fold=fold)
        round_trip = aware.astimezone(UTC).astimezone(zone).replace(tzinfo=None)
        if round_trip == local_naive:
            candidates[fold] = aware
    return candidates
```

Require `timezone_fold` only for ambiguous exact times. Reject transition-crossing windows until their endpoints map unambiguously.
