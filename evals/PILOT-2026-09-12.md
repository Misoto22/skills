# Evaluation harness pilot — 2026-09-12

This report records the bounded pilot used to validate the experimental evaluation harness. It
contains aggregate results only. Raw model content, request headers, credentials, gateway details,
machine-local paths, and ignored run artifacts are intentionally excluded.

## Scope

The pilot exercised one tuning case from each of three skill shapes:

- text transformation: `tempering/three-registers-keep-the-date`;
- structured interpretation: `synastry-reading/neutral-context-omits-sensitive-domains`;
- tool execution: `reunite/synthetic-sandbox-merge`.

Each completed comparison used three samples per arm, zero retries, separate candidate and judge
requests, and provider-supported reasoning disablement. The candidate and judge were separately
configured but mapped to the same model deployment. Operator-supplied deployment provenance attests
the gateway mapping used by the final runs; it does not attest immutable vendor weights.

## Valid aggregate results

| Shape | With skill | Without skill | Criteria passed | Mechanical evidence |
| --- | ---: | ---: | ---: | --- |
| Text transformation | 0/3 cases | 0/3 cases | 10/18 | No mechanical failures |
| Structured interpretation | 0/3 cases | 0/3 cases | 13/18 | 14 with-skill and 37 without-skill findings |

These are automated measurements, not accepted skill regressions. The final text and structured
runs completed without void samples and produced trusted usage and deployment-mapping evidence.
Their failed outputs require human review before changing a skill or its rubric.

Human calibration reviewed all six text samples separately from the immutable automated record. It
scored the with-skill arm at 1/3 cases, the without-skill arm at 0/3 cases, and 11/18 criteria overall,
identifying two automated false negatives and one automated false positive. This calibration does
not replace the automated 0/3 versus 0/3 case result or its 10/18 criterion record.

The tool pilot proved the real boundary independently: the declared `merge` command executed with
exit code zero, copied two synthetic entries, wrote its manifest, and passed every artifact check.
A completed single-sample run passed all mechanical checks. Its automated judge marked two of three
criteria true; human review found the third judgment was a false negative because the answer already
located the effects inside the synthetic fixture. The human calibration result is therefore three of
three criteria, while the immutable automated record remains unchanged.

No complete six-sample tool comparison is reported. Successive runs exposed tool-interface defects
initially classified as fatal. The harness correctly stopped after each resulting void; later free
fixes made the bounded cases recoverable. The retained partial evidence proves successful merges and
artifact checks, but it is not an N3 comparison and must not be promoted into one.

## Harness findings from the pilot

The pilot found and closed failures that local schema checks alone did not expose:

- judge output originally lacked an explicit top-level schema and 1-based criterion identifiers;
- blank candidate output was initially scored as a quality failure instead of voiding the run;
- missing files, directory reads, and unknown named commands needed recoverable tool responses;
- tool command names needed an enum so a name could not be mistaken for shell arguments;
- partial trajectories and artifact checks needed to survive later tool failures;
- temporary sandbox paths needed redaction before command output returned to the model;
- response model aliases needed operator-supplied deployment provenance before a version gate could
  treat model identity as comparable.

The initial 1,000-token judge failures and later schema-contract failures are retained as invalid
harness runs and excluded from quality scores. A later 4,000-token response ended normally and still
failed the old contract, which established that truncation was not the sole cause. After the prompt
and parser were aligned, the judge produced valid structured criteria.

## Cost and budget evidence

The experiment used an 80 CNY shared allocation, with a further 20 CNY left unallocated inside the
100 CNY authorization. Usage-complete runs account for 1.221042 CNY using the repository's
conservative dated pricing policy. Runs without trustworthy usage retain 2.284 CNY of their original
reservations instead of releasing it. The process-shared ledger therefore holds 3.505042 CNY across
16 run records, or about 4.38 percent of the shared allocation.

These amounts are harness accounting based on recorded token usage and conservative rates. They are
not presented as a provider invoice. An independent final SpendLogs reconciliation counted 254,231
tokens and estimated 1.467978 CNY under the conservative 3/12 CNY token rates. Its USD logger is also
telemetry rather than an invoice. This independent estimate is distinct from the ledger's 3.505042
CNY held total, which includes reservations for runs without trustworthy usage. The ledger remains
fail-closed: malformed state, non-finite amounts, overspend, or untrusted usage cannot free reserved
budget.

## Native Claude boundary

The Claude path in this release is schema export and validation only. No native Claude behavioral
quality result is claimed by this pilot. A future native run must use the exported suite through an
approved evaluator and produce its own usage, model, and budget evidence before it can be compared
with these OpenAI-compatible runs.

## Interpretation limits

This pilot sampled one tuning case per skill shape. It did not execute the held-out phase or a valid
before-and-after skill iteration, so it cannot approve a skill release or claim general quality
improvement. Same-model judging is recorded as a limitation. Automated failures remain measurements
to inspect, and the report keeps human calibration separate from immutable machine results.
